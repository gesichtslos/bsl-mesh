# 17. Локальная телеметрия P0.6

Сбор по умолчанию выключен. Сервер принимает только явно отправленный отчёт и хранит его как непроверенный. Рейтинг окружений не строится.

Три слоя не вызывают друг друга сами:

1. Локальный сборщик читает Cursor Hooks и складывает короткие записи в каталог вне Git.
2. Сборка результата связывает эти записи с задачей, которую владелец начал и завершил локальной командой.
3. `POST /api/v1/telemetry/reports` принимает уже собранный JSON. Сборщик не исполняет команды сервера, сервер не читает рабочий каталог.

## Команды

`pnpm telemetry` после сборки, либо `node dist/telemetry/main.js`. Каталог данных: `BSLMESH_TELEMETRY_HOME`, иначе `$XDG_DATA_HOME/bsl-mesh/telemetry` или `~/.local/share/bsl-mesh/telemetry`.

- `status` — включён ли сбор и какие источники подтверждены;
- `enable-local` — включить запись на этот компьютер;
- `disable` — остановить запись, не удаляя её;
- `list` — задачи;
- `task-start --family <token> [--form unknown|ordinary|managed] [--organic] [--mcp-id <id>]`;
- `task-attempt --task <id>` — следующая попытка внутри той же задачи;
- `task-finish --task <id> --outcome <status> [--method ... --origin ... --exit-code N]`;
- `preview --task <id>` и `export --task <id> --out <file>`;
- `submit --task <id> --server <origin>` — нужен `BSLMESH_TELEMETRY_TOKEN`, запрос не выполняется сам;
- `import-sdk --task <id> --file <json>` — готовый результат SDK, без нового запуска;
- `delete-local --confirm` — отдельное удаление накопленных локальных записей.

Пока задача открыта, новые сессии Cursor присоединяются к ней. Без открытой задачи сессия не создаёт задачу. `sessionEnd` и `stop` не переводят задачу в успех. Для `success_verified` обязательны метод и происхождение проверки. Код выхода 0 сам по себе остаётся наблюдением.

Неизвестное измерение записывается как `state: "unknown"` и `value: null`. Ноль подставляется только когда источник действительно сообщил ноль.

## Cursor Hooks

Рабочий проект не содержит активного `.cursor/hooks.json`. Пример лежит в `docs/examples/cursor-telemetry-hooks.json`. Его можно скопировать в `.cursor/hooks.json` или `~/.cursor/hooks.json` только отдельным решением владельца. Глобальные hooks установщик не включает.

Команда hook читает stdin, оставляет allowlist и всегда завершается кодом 0 с телом `{}`. Она не возвращает `followup_message` и не продолжает разговор из `stop`. Ошибка телеметрии не меняет ответ агента.

На диск не попадают `tool_input`, `tool_output`, `prompt`, `error_message`, `transcript_path`, `workspace_roots`, `user_email`, пути и аргументы. Идентификатор беседы Cursor заменяется локальным SHA-256 и в отчёт не входит.

Пробная задача читала синтетический файл во временном каталоге и один отсутствующий путь. Обезличенный отчёт: `docs/examples/telemetry-report.sample.json`. Он не отправлялся на сервер. Сессия в отчёте собрана из идентификатора беседы внутри событий инструментов: `sessionStart` и `sessionEnd` в этой уже открытой сессии не приходили, поэтому длительность сессии неизвестна. Календарное время включает ожидание человека и не записано как время работы агента. `tool_busy_ms` меньше суммы длительностей, потому что перекрывающиеся вызовы не складываются как прошедшее время.

## Снимок окружения

Снимок берётся при старте задачи и ещё раз при завершении. Если версия, модель или контрольные суммы Rules/Skills изменились, добавляется новый снимок, старый не переписывается. В отчёт входят имена и SHA-256, не текст Rules, Skills и не содержимое MCP-конфигурации. Неизвестная версия MCP остаётся `null`. Тип BSL-задачи сборщик из репозитория не угадывает: его задаёт `--family` и `--form`.

## Сервер

Нужен credential со scope `telemetry:write`. Это не `cases:write` и не флаг публичной публикации. Повтор того же `report_id` и того же документа не создаёт вторую строку. Другое тело с тем же идентификатором — `409`. После отзыва credential новая отправка получает `401`. Чужой отчёт читается как отсутствующий. `source_kind=synthetic` не попадает в выборку `organic`. Ответ всегда содержит `acceptance: "stored_unverified"` и `independent_owner_confirmations: 0`: несколько агентов одного владельца не становятся независимыми подтверждениями.

Схема: `docs/schemas/telemetry-report.schema.json`. HTTP: `docs/openapi/telemetry.openapi.json`.

## Резервная копия и удаление

Локальные файлы — это `state.json` в каталоге телеметрии. Их копируют вместе с этим каталогом. Серверная копия принятых отчётов входит в обычный backup PostgreSQL. `disable` ничего не стирает. `delete-local --confirm` стирает локальные задачи и сессии. Строка миграции и таблица `telemetry_reports` при этом остаются.

## Откат

Удалить таблицу `telemetry_reports`, вернуть прежнюю проверку `credentials.scopes` без `telemetry:write` и убрать строку `010_telemetry_reports.sql` из `schema_migrations`. Код маршрута удаляется вместе с веткой. Уже принятые отчёты после отката таблицы недоступны, поэтому перед откатом нужна копия базы. Локальный каталог телеметрии откат сервера не трогает.
