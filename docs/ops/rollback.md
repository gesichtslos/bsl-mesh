# Процедуры остановки и восстановления

Эти команды разделены специально. Откат версии приложения не удаляет том базы. Восстановление дампа не останавливает Compose с удалением томов. Полное удаление локального окружения не является откатом.

## 1. Остановить

`scripts/stop.sh` выполняет `docker compose stop`. Контейнеры останавливаются, том PostgreSQL сохраняется.

Запуск снова: `docker compose start`.

## 2. Откатить версию приложения

`scripts/rollback-app.sh <image>` пересоздаёт только сервис `app` из уже скачанного локального образа. База и её том не изменяются. Пример для текущего образа:

```bash
scripts/rollback-app.sh bsl-mesh-app:0.1.0
```

Если нужного образа нет локально, команда завершается до пересоздания контейнера.

## 3. Восстановить резервную копию

Снять дамп рабочей базы:

```bash
scripts/backup.sh
```

Восстановить его в отдельную базу и проверить служебную строку:

```bash
scripts/restore-backup.sh backups/bslmesh_dev-TIMESTAMP.dump bslmesh_restore
```

По умолчанию цель `bslmesh_dev`, `postgres` и template-базы отклоняются. Восстановление прямо в рабочую базу требует отдельного `CONFIRM_RESTORE_APP_DATABASE=yes` и цели `bslmesh_dev`. Репетиция `scripts/rehearse-backup.sh` восстанавливает копию в `bslmesh_restore`, проверяет её и удаляет только эту копию.

## 4. Уничтожить локальное тестовое окружение

`scripts/destroy-test-env.sh` удаляет контейнеры и тома только при `CONFIRM_DESTROY_TEST_ENV=yes`. Без этого флага команда отказывается и подсказывает три процедуры выше. `docker compose down -v` не используется как обычный откат.
