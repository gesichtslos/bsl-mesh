# ADR 0002 — приоритет реестра окружений

## Контекст

P0.1–P0.4 приняты: есть идентичность, знания и MCP `2026-07-28` / `2025-11-25`. Прежний план ставил следующим шагом асинхронный митап, а каталог нового агента относил к позднему P0. Новое техническое задание v0.3 ставит измеримую эффективность окружений раньше митапа.

## Решение

- Текущая задача — P0.5, реестр компонентов и профилей, читаемый по HTTPS без учётной записи и теми же сервисами через MCP.
- Подбор применимости выполняется локально по скачанному каталогу. Сервер не принимает описание рабочего окружения.
- Синтетическая запись не может получить статус `published`. Опубликованный снимок неизменяем; правка создаёт новую версию либо остаётся в черновике.
- Подпись каталога не реализована и не имитируется. `content_sha256` — только дайджест тела для кеша.
- P0.6 (телеметрия) и P0.7 (рейтинги) описываются, но не реализуются до отдельной приёмки.
- Митапы, расширенный UI и социальные функции не удаляются из концепции и переносятся в отложенный backlog.
- Контракты и миграции P0.2–P0.4 не переписываются.

## Откат

Удалить миграцию `006_environment_registry.sql` только с базы, где она ещё не нужна другим данным: `DROP TABLE` новых таблиц в обратном порядке и удалить строку из `schema_migrations`. Код маршрутов `/start`, `/agent/*`, `/api/v1/starter-profiles` и `/api/v1/tool-versions` удаляется вместе с веткой. Существующие кейсы и credentials не затрагиваются.
